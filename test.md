## Object-Oriented Design Notes

- **Encapsulation:** The cart state is only mutated inside `CartController` methods such as `add`, `update`, `remove`, and `applyCoupon`, which clamp quantities to available stock while hiding the raw session payload; the shared `Database` helper also keeps its PDO handle private behind `getConnection()`.【F:controllers/cart/CartController.php†L7-L130】【F:includes/config.php†L31-L65】
- **Abstraction:** A reusable `BaseRepository` wraps CRUD logic and connection bootstrapping so higher layers interact with repositories like `ProductRepository`, `ClientRepository`, and `InvoiceRepository` instead of hand-written SQL in every controller.【F:repositories/BaseRepository.php†L1-L69】【F:repositories/ProductRepository.php†L1-L74】【F:repositories/client/ClientRepository.php†L1-L70】【F:repositories/invoice/InvoiceRepository.php†L1-L40】
- **Inheritance:** Each repository extends `BaseRepository` to inherit the PDO connection and helpers for inserts, updates, and deletes, which keeps module-specific classes thin and focused on domain fields.【F:repositories/ProductRepository.php†L1-L74】【F:repositories/client/ClientRepository.php†L1-L70】【F:repositories/invoice/InvoiceRepository.php†L1-L80】
- **Polymorphism:** Price handling is currently implemented with simple conditionals (e.g., coupon toggles and payment-method branching), highlighting the next step of extracting strategy-style calculators (`PriceRule` implementations such as `BulkDiscount` or `CouponPercent`) that can be injected into `InvoiceWorkflow` once they exist.【F:controllers/cart/CartController.php†L116-L126】【F:services/InvoiceWorkflow.php†L17-L45】
- **Composition over inheritance:** `CheckoutController` composes multiple collaborators (`ClientRepository`, `InvoiceRepository`, `InvoiceWorkflow`, and `AddressService`) and `InvoiceWorkflow` composes `InvoiceRepository` to persist invoices, keeping orchestration logic outside the persistence layer.【F:controllers/checkout/CheckoutController.php†L15-L190】【F:services/InvoiceWorkflow.php†L5-L45】
- **Namespaces & Autoloading:** Composer already declares PSR-4 autoloading for the project namespace while legacy modules still rely on the `loadRepo` helper—migrating those includes into the autoloaded tree will align runtime wiring with the namespace plan.【F:composer.json†L13-L16】【F:includes/config.php†L61-L65】
- **Exceptions & error contracts:** Controllers currently surface errors via flash messages or `die()` calls; introducing domain exceptions (e.g., `OutOfStock`, `InvalidQuantity`) that map to 409/422 responses will let us replace those manual exits with consistent API contracts.【F:controllers/checkout/CheckoutController.php†L71-L178】
